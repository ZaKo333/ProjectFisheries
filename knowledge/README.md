| **B. 标准摘录** | 取自 `GB 11607-1989` 官方扫描原文，并附标准编号与条款号 | ✅ 已逐条核对 |
| **C. 数据集派生** | 从数据集本身提取的类别定义、字段含义、量纲判定 | ✅ 已实测 |

### 🟢 语料核验状态（2026-10-15 起）

**9 篇语料全部 `verified: true`。** 这个标记现在有实际含义，说明每篇文档中
**所有引用标准编号与水质数值都已与标准原文或标准平台的状态字段比对过**。

核验方式与来源：

| 项 | 来源 |
|---|---|
| 水质限值原文 | 生态环境部公开的 `GB 11607-1989` 官方扫描 PDF（5 页），逐页比对表1 与附录A |
| 标准现行性 | `openstd.samr.gov.cn`（国家标准全文公开系统）、`std.samr.gov.cn`（全国标准信息公共服务平台，字段 `STATE` / `FZ_DATE`） |

**两条关键结论**（推翻了此前的误判）：

1. **`GB 11607-1989` 仍为现行**，没有被任何版本替代；
   **不存在 `GB 11607-2022`** —— 该标准号检索结果为 0 条。
2. 早期引用的 **`NY 5051-2001`、`NY 5071-2002`、`NY 5072-2002` 已于 2025-01-17 废止**，
   且查不到直接替代标准，因此**删除引用**（而不是"升级到新版"）。
   渔药方向改用现行有效的 **`NY/T 755-2022`**。

> **边界说明**：`verified: true` 只覆盖"引用的标准数值与编号是否正确"。
> 它**不**意味着本项目的工程分级（警戒线、危险线、红线、权重）
> 获得了标准背书——那些仍是工程判断，在各文档中已与标准数值分别标注。

## 2. 语料组织约定

### 2.1 元数据头

每个文档以 YAML front-matter 开头，供检索时按条件过滤：

```yaml
---
doc_id: water_threshold
title: 淡水池塘养殖水质指标阈值与分级
category: 水质        # 水质 / 病害 / 投料 / 应急 / 标准
disease: null         # 烂鳃 / 出血 / 水霉 / null
indicators: [dissolved_oxygen, ammonia_n, nitrite_n, ph, water_temp]
risk_levels: [正常, 预警, 高危]
source: 标准原文 + 工程扩展
verified: true        # ← 是否已与标准原文核对
standard_codes: [GB 11607-1989]                      # 引用到的标准编号（含发布年份）
access_source: 生态环境部公开的 GB 11607-1989 官方扫描原文
verified_by: 项目组（逐条比对 GB 11607-1989 官方扫描原文）
verified_on: 2026-10-15
---
```

`category` 与 `disease` 字段让检索可以做**条件过滤**：
当图像识别出"烂鳃"时，检索可以限定 `category="病害" AND disease in ("烂鳃", null)`，
避免检索到无关的水霉处置方案。

**核验类字段的用途**

| 字段 | 说明 |
|---|---|
| `standard_codes` | 该文档引用到的标准编号（含年份）。检索结果会带进 prompt，让模型能直接说"依据 GB 11607-1989 表1 序号 5" |
| `access_source` | 核验时**实际访问**的来源，便于他人复现核验 |
| `verified_by` | 核验人。`verified: true` 时不应为空，否则核验无从追溯 |
| `verified_on` | 核验日期（`YYYY-MM-DD`）。写成不加引号的日期也可以，加载时会统一成字符串 |

> 这四项是 `DocMeta` 的**可选字段**（默认空），只有需要溯源的文档才填。
> 条款原文不单列字段，而是**直接写进正文**并配 `[标准编号 条款]` 锚点——
> 数值脱离上下文单独存一份反而容易与正文漂移。

### 2.2 标题层级 = 分块边界

分块策略按**标题层级切分**（二级标题为一个 chunk），
每个 chunk 携带其所属的文档标题链作为上下文前缀，提升检索命中率。

**表格整体保留不切分**——阈值表格被切断会丢失行与列的对应关系。

### 2.3 引用标记

正文中形如 `[GB 11607-1989 表1 序号5]`、`[SC/T 7201.2-2006]` 的方括号标记是
**引用锚点**，会被索引进 chunk 元数据（字段 `citation_keys`），便于回答时给出来源。

> ⚠ **不要引用已废止标准**。已退役的编号（`NY 5051-2001`、`NY 5071-2002`、
> `NY 5072-2002`、`GB/T 22213-2008`）仅在 `08_标准与依据.md` 的
> 「已停用标准」表里出现，用于说明退役决定，**不作为依据引用**。

## 4. 入库流程

仓库**不含** `chroma/`（见 §3），克隆下来第一次必须先构建一次；之后只有语料改动了才需要重建。

```powershell
cd <工程>
$env:PYTHONPATH = "$PWD\src"
.\.venv\Scripts\python.exe scripts\build_knowledge_base.py          # 全量重建
.\.venv\Scripts\python.exe scripts\build_knowledge_base.py --stats  # 只看统计
```

首次运行会下载中文向量模型 `BAAI/bge-small-zh-v1.5`（约 90 MB，ONNX 格式，
**不需要 PyTorch**）。下载后缓存在本地，之后离线可用。
