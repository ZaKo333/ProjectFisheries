# M10 回译层说明（D12：英文提示词 + 回译成中文）

> 面向要复现、要换模型、或要判断"这套东西到底靠不靠得住"的人。
> 代码在 `src/fisheries/agent/translate.py`，演示在 `scripts/demo_translate.py`，
> 单测在 `tests/unit/test_translate.py`。

---

## 1. 为什么需要这一层

`KurmaAI/AQUA-7B` 是 `Mistral-7B-Instruct-v0.3` 的**英文微调**，HuggingFace 标签写着
`language: en`。要它直接写高质量中文没有保证，但竞赛评委与养殖户要的都是中文。

所以本项目的做法不是"教它写中文"，而是：

```
水质/图像数据 ──► 英文提示词 ──► AQUA-7B 用英文写建议 ──► 回译层 ──► 中文报告
                  (prompts.py)      (risk_level 仍照抄中文枚举)   (translate.py)
```

回译层只碰**话怎么说**，碰不到**风险几级**：`risk_level` 与 `alerts` 一个字都不过翻译，
它们是护栏要比对的标识符与融合层的确定性结果。

### 1.1 曾经的问题：收益是名义上的

原来的 `auto` 分派只看"有没有配远端翻译模型"，分派顺序是
`llm`（有 client）→ `glossary`（否则）。

而 `glossary`（词表后端）有一条硬上限：**`max_words = 6`**。
这不是保守，是实测——超过 6 个英文词以后，即使每个词都在词表里，逐词拼出来的中文
**语序也是错的**：

```
Measure dissolved oxygen and ammonia nitrogen again tonight
  → 检测溶氧并氨氮再今晚          ← 逐词硬译的结果，读不通
```

AQUA-7B 产出的自由长句**必然超过 6 词**。于是：

- 词表后端整句拒绝 → 退回规则模板 → **AQUA-7B 的输出被整条丢掉**；
- 离线机器（没有远端翻译模型）→ 必然落到词表后端 → **D12 的收益等于 0**。

这就是"收益名义化"：架构上装好了回译层，实际一个字的模型输出都没用上。

### 1.2 修法

补一个**本地离线翻译模型**，让它成为 `auto` 的第一选择。
详见第 2 节（模型）与第 3、4 节（分块与后订正）。

## 2. 本地离线翻译模型

### 2.1 选型

| 候选 | 结论 |
|---|---|
| `Helsinki-NLP/opus-mt-en-zh` | ✅ **默认**。Marian 专用英中 NMT，约 77M 参数，CPU 单句 0.3–0.7 s |
| `Qwen/Qwen2.5-0.5B-Instruct` | 备选，通用小模型，中文更自然但慢、且要自己写提示词 |
| `qwen-translate` | ❌ **不存在这个名字的可下载模型**。需求里提到的这个名字没有对应实体 |

值得说清楚的一件事：**通用 NMT 不懂水产**（第 4 节有实测错法）。
但它的失败方式和词表后端**正好互补**——
词表后端是"词认得、语序拼不出"，NMT 是"语序对、术语全错"。
所以设计上让 **NMT 负责语序、词表负责术语**。

### 2.2 下载

权重不在 PyPI 上，要单独下（约 315 MB）：

```powershell
pip install -e ".[translate]"        # transformers + sentencepiece + sacremoses
.\.venv\Scripts\python.exe scripts\fetch_translate_model.py
.\.venv\Scripts\python.exe scripts\fetch_translate_model.py --list      # 看还有哪些可选
```

脚本优先走 **ModelScope**（`www.modelscope.cn` 在本机可达），失败再试 HF 镜像
`hf-mirror.com`（本机实测其 API 返回 403，仅作备用路径；`huggingface.co` 直连超时）。
它按文件大小做幂等跳过，重跑只会打印 `[skip]`。

下载后目录（`models/translate/opus-mt-en-zh/`）：

| 文件 | 大小 |
|---|---|
| `pytorch_model.bin` | 312,087,009 B |
| `vocab.json` | 1,617,791 B |
| `source.spm` / `target.spm` | 806,435 / 804,600 B |
| `config.json` / `generation_config.json` / `metadata.json` / `tokenizer_config.json` / `configuration.json` | 共约 3.2 KB |

### 2.3 配置

```powershell
$env:FISHERIES_TRANSLATOR_MODE        = "auto"     # auto / local / glossary / llm / bypass
$env:FISHERIES_TRANSLATOR_LOCAL_DIR   = "D:\models\translate"   # 模型根目录，默认 <项目>/models/translate
$env:FISHERIES_TRANSLATOR_LOCAL_MODEL = "opus-mt-en-zh"         # 目录名或绝对路径
```

`auto` 的分派顺序是 **本地模型 → 远端中文模型 → 词表兜底**。

### 2.4 本地模型为什么需要 `torch` / `transformers`

这两个依赖是**惰性 import** 的：没装 `[translate]` extra 时
`import fisheries.agent.translate` 照常成功，只是 `local` 不可用、自动退回词表后端。
`local_model_available()` 会返回**可照做的原因**（缺目录 / 缺 `config.json` / 缺权重 /
缺 `transformers`），这个原因会进 `degraded_reasons` 而不是被吞掉。

### 2.5 一个 Windows 特有的坑：sentencepiece 打不开非 ASCII 路径

本项目的路径里有中文（`D:\设置\项目\Agent\project\...`），而 sentencepiece 的 C++ 加载器
在 Windows 上走**窄字符 / ANSI 代码页**路径：

```
RuntimeError: NOT_FOUND: "D:\设置\项目\...\source.spm": No such file or directory Error #2
```

文件明明存在。`_loadable_path()` 的处理是：路径是纯 ASCII 就直接用；否则尝试
`os.path.relpath()`，相对路径也是 ASCII 就用相对路径。同一个字符串同时喂给
tokenizer 和 model 的 `from_pretrained`，所以两者一起被覆盖。

## 3. 分块：为什么必须限长

### 3.1 现象

模型一次吞下整段英文会**把尾部整段丢掉**。标尺句（106 字符 / 17 词）：

```
Turn on the aerator tonight and measure dissolved oxygen
and ammonia nitrogen again tomorrow morning at 6.
```

默认给到 **200 字符 / 40 词**时，模型输出：

```
今晚打开气动器 测量溶解氧气和氨氮
```

`again`、`tomorrow morning`、`at 6` 全丢，**连数字 6 都没了**。
数值校验（`numbers_preserved`）能发现"数字少了"，但无法知道少的是哪一句，
只能把整条字段放弃——这就是需求里说的"长句回译错乱"。

### 3.2 实测：词预算才是那条线

探针逐档收紧预算，判据是**数字 6 还在不在**：

| 字符预算 | 词预算 | 实际切出 | 结果 |
|---|---|---|---|
| 200 | 40 | 1 块 | ✘ 丢 `at 6` |
| 140 | 28 | 1 块 | ✘ 丢 `at 6` |
| 110 | 20 | 1 块 | ✘ 丢 `at 6` |
| 90 | 16 | 2 块 | ✔ 6 保住 |
| 70 | 12 | 2 块 | ✔ |
| 55 | 9 | 3 块 | ✔ |

**结论：词预算是那条线，字符预算不是。** 17 词的句子只要不切就必丢尾部。

### 3.3 为什么取 110 / 16 而不是更小

因为**切得越碎，模型越容易把术语译错**：

| 预算 | `quicklime` 的译法 |
|---|---|
| 200 | 生石灰 ✔ |
| 70 | 快生石灰灰 ✘ |

所以取"刚好够切开"的 **110 字符 / 16 词**（`DEFAULT_CHUNK_CHARS` / `DEFAULT_CHUNK_WORDS`），
不再往下压。

### 3.4 副作用：预算是重试触发器，不是固定开销

`chunk_text()` 的语义是"**超预算才切**"：

- 预算内的短句（`timing`、指标名、`dissolved oxygen is low`）→ 一次调用，
  **与改造前完全相同**，延迟和质量零变化；
- 超预算的长句 → 才走多块。

切分粒度从贵到便宜：句边界（`。！？；` / `.!?;`）→ 小句边界（逗号、顿号、冒号，
或 `and|or|then|but|while|because|so|after|before|until|when|if`）→ 词级硬切。
**硬切不会切在数字与单位之间**，`1.5 mg/L` 是一个整体（`_glue_number_units`）。
最后相邻碎片会合并回去，避免切得过碎。

### 3.5 失败语义：任一块失败 ⇒ 整条字段放弃

`_translate_chunked()` 是 `LLMTranslator` 与 `LocalTranslator` 共用的骨架：

- 块数 > `DEFAULT_MAX_CHUNKS`（24）→ 整条放弃；
- 任一块翻译失败 → 整条字段放弃（**不做半英半中**）；
- 拼起来后再做一次 `numbers_preserved` 与"英文残留"检查。

## 4. 后订正：让词表管术语

### 4.1 现象

NMT 译得通顺，但领域词几乎全错。实测（载体句 `The pond shows abnormal {term} today.`，
逐条送词表的英文键）：

| 英文 | 模型给的 | 本工程要的 |
|---|---|---|
| `dissolved oxygen` | 溶解氧 / 破解的氧气 | 溶氧 |
| `nitrite nitrogen` | 亚硝酸氮 | 亚硝酸盐 |
| `turbidity` | 多发性 | 浊度 |
| `non-ionized ammonia` | 非离子化氨 | 分子氨 |
| `bacterial gill disease` | 细菌刺痛病 | 烂鳃病 |
| `gill rot` | 刺状腐烂 | 烂鳃病 |
| `bacterial red disease` | 细菌红病 | 细菌性败血症 |
| `hemorrhagic septicemia` | 出血性败血症 | 细菌性出血病 |
| `saprolegniasis` | 沙普罗尼丝虫病 | 水霉病 |
| `aerator` | 呼吸器 / 气动器 | 增氧机 |
| `aeration` | 发热 | 增氧 |
| `stocking density` | 丝袜密度 | 放养密度 |
| `population` | 人口 | 存塘量 |
| `probiotics` | 先生生物 | 益生菌 |
| `zeolite` | 佐利特 | 沸石 |
| `quicklime` | 速石 / 速溶液 | 生石灰 |
| `bleaching powder` | 漂白粉粉 | 漂白粉 |
| `netting` | 网状图 | 拉网 |
| `bottom sediment` | 海底沉积物 | 底泥 |
| `medicated feed` | 药物喂养 | 药饵 |
| `water exchange` | 水交换 | 换水 |
| `tonight` | 表演 | 今晚 |
| `NTU` | **纽芬兰先令** | NTU |
| `celsius` | 西里乌斯 | ℃ |

词表后端的失败是"词认得、语序拼不出"，NMT 的失败是"语序对、术语全错"——
**两者互补**。所以：

```
NMT 先出通顺中文  ──►  中文→中文的后订正表（GLOSSARY_POST_ZH）  ──►  单位规范化
```

### 4.2 收录标准

**只收"本领域里不可能有第二种解释"的错法。**

三条**故意不收**，并且理由写进了代码 docstring：

| 错法 | 为什么不收 |
|---|---|
| `measure` → 措施 | "采取措施"是正当中文，收了会改坏 |
| `turbidity` → 发病率 | 它本身是正当的病害统计词 |
| `centigrade` → 中度 | "中度污染"是正当中文 |

这类错法是**开放的**：换个句子可能又变一个词。表只能覆盖实测到的，
发现新的就补一行。复现方法见第 6 节。

### 4.3 级联保护

后订正表用**一次扫描的交替正则 + 最长优先**（`_compile_alternation`），
不是逐条 `str.replace`。原因是表里有包含关系：

```
亚硝酸 ⊂ 亚硝酸盐
亚硝酸氮 ⊂ （更长，优先匹配）
```

逐条 `sub` 会把刚改好的 `亚硝酸盐` 再切一次。

**但"一次扫描 + 最长优先"只解决了替换结果被再次替换的问题，没解决一个更隐蔽的坑**：
交替正则匹配的是**输入**，而 `亚硝酸盐`（本工程认定的正确写法）自己并不是一条规则的键，
于是输入的 `亚硝酸盐` 会被 `亚硝酸` 匹配掉前三个字，替换成 `亚硝酸盐`，末尾那个 `盐` 留在原地——
得到 **`亚硝酸盐盐`**。

这个缺陷在补测试时才被抓住（原先文档写了断言，但代码里没有对应的测试守着）。
修法是给 `亚硝酸盐` 补一条**恒等规则**占位，让它作为一个整体被消费掉：

```python
("亚硝酸盐", "亚硝酸盐"),   # 占位：让正确写法整体被消费，不被"亚硝酸"切碎
```

并补了一条**通用不变量测试**，把这类缺陷一次性管住——对表里的**每一条** `(k, v)`，
要求 `fn(v) == v`（替换结果必须能被同一个正则原样消费）：

```python
post_edit_terms("亚硝酸盐") == "亚硝酸盐"     # 不能被切坏
post_edit_terms("亚硝酸")   == "亚硝酸盐"
post_edit_terms("采取措施") == "采取措施"     # 未收录的词原样保留
```

见 `tests/unit/test_translate.py::TestPostEdit::test_every_replacement_is_itself_stable`
与 `test_the_placeholder_is_actually_needed`（后者证明那条恒等规则是必要的，不是顺手加的）。
**以后往表里加规则，这条不变量会自动检查新规则的替换结果是否稳定。**

### 4.4 单位规范化

`normalize_units()` 在**术语替换之前**跑，把模型的中文单位写法收回工程口径：

| 模型给的 | 规范化后 |
|---|---|
| 毫克/升、毫克∕升、毫克每升、mg/升、毫克/公升 | `mg/L` |
| 微克/升、微克每升 | `μg/L` |
| 摄氏度、`°C` | `℃` |
| 百万分之 | `ppm` |
| 纽芬兰先令 | `NTU` |
| 西里乌斯 | `℃` |

并在数字与单位之间补一个空格（`1.5毫克/升` → `1.5 mg/L`、`42NTU` → `42 NTU`）。

## 5. 实测效果

### 5.1 改造前 vs 改造后（同一份报告逐字段回译）

| 后端 | `n_translated` | `n_replaced` |
|---|---|---|
| `glossary`（改造前的离线默认） | 1 | 4 |
| `local`（现在） | **6** | **0** |

`n_replaced` 是被规则模板替换掉的字段数——**这就是"AQUA-7B 的输出被整条丢掉"的量化**。

### 5.2 长句

输入（第 3 节的标尺句）：

```
Turn on the aerator tonight and measure dissolved oxygen and ammonia nitrogen again tomorrow morning at 6.
```

输出：

```
今晚打开增氧机测量溶氧明天早上6点再有氨氮和氨氮
```

**数字 6 保住了、无英文残留。** 语序一般（"再有"是模型自己加的），这是分块的已知代价。

### 5.3 带病名与投入品的长句

```
池塘显示异常浊度,鱼有细菌刺状疾病; 立即增加空气循环,停止两天的喂食,
在黎明前施用每立方米20克的生石灰。
```

`turbidity`、`quicklime`、20 g/m³ 都到位；`bacterial gill disease` 只订正到
"细菌刺状疾病"（表里收了"细菌刺状疾病 → 烂鳃病"，此处是分块后另一种变体）。

## 7. 已知限制

1. **分块之后语序仍然一般。** 各块独立翻译再拼接，跨块的指代与连接词会失真
   （上面的"再有"）。要根治得换更强的模型，不是调预算能解决的。
2. **后订正表是开放集合。** 只覆盖实测到的错法；换个句子可能又冒一个新错法。
3. **本地模型只用于回译，不参与推理。** AQUA-7B 仍然是 7B、fp16 约 15 GB 显存，
   `opus-mt-en-zh` 那 315 MB 换不掉它。
4. **中文质量的上限由模型决定。** `opus-mt-en-zh` 是 2020 年前后的 NMT，
   中文自然度不如现代大模型；它的价值是**离线、确定、零 key**，
   以及把 `glossary` 从"默认"降为"兜底"。
5. **没装 `[translate]` extra 时回到旧行为**：退回词表后端，
   超过 6 个英文词的自由长句仍会被整条拒绝。这不是回归，是没部署。
