> 这份文档回答一个问题：**图像模态从"模拟兜底"变成"真实模型"，是怎么做到的，以及别人怎么复现。**

## 0. 一句话结论

`fish_disease_detect` 的默认后端现在是真实训练的 **YOLOv8n-cls 四分类权重**
`models/yolov8-fish.pt`（2,980,669 B，sha256 `95a9bb0d…96da7`）。
本机测试集 186 张：**Top-1 93.0%、macro F1 93.0%、mAP@0.5（弱口径）92.9%**。

工程**不强制**带这份权重：权重缺失时工具自动落回 mock 兜底并在响应里标
`degraded_mode=true`，`/api/v1/health` 也会如实申报 `mock`。这样"没训练过"的机器
照样能跑全部演示与测试（详见 §6）。

## 1. 为什么要训：原来的缺口

改造前 `src/fisheries/tools/fish_disease.py` 是确定性兑底实现：
`MOCK_MODEL_VERSION = "mock-v0.1"`，按文件内容哈希（或目录名提示）编造类别概率。
问题不在于"演示不好看"，而在于**融合层会把假分数当证据用**——
`SEVERE_DISEASE` / `DISEASE_DETECTED` 会因一个假置信度触发，
于是"多模态融合"这个卖点站不住。

改造后同一条链路里流动的是真实推理置信度，融合层**一行没改**
（水位权重 0.6 / 视觉 0.4 保持不变，见 `src/fisheries/fusion.py`）。

## 2. 环境：装什么、为什么这么装

实测版本（本机 Windows + Python 3.13.2）：

| 组件 | 版本 |
|---|---|
| Python | 3.13.2 |
| torch | 2.8.0+cu128 |
| torchvision | 0.23.0+cu128 |
| ultralytics | 8.4.177 |
| CUDA runtime | 12.8（wheel 自带） |
| GPU | NVIDIA GeForce RTX 5070 Laptop GPU，cc (12, 0)，8151 MiB |

**为什么必须是 cu128**：RTX 5070 是 Blackwell 架构，算力等级 **sm_120**。
比它早的 CUDA wheel（cu118 / cu121 / cu124）里没有 sm_120 内核，
装上去能 import 但一跑推理就报 `no kernel image is available for execution`。

```powershell
cd <工程>

# 1) torch 走 PyTorch 官方 cu128 索引
.venv\Scripts\python.exe -m pip install torch torchvision `
    --index-url https://download.pytorch.org/whl/cu128

# 2) ultralytics 走清华镜像（它依赖的 opencv-python 等在这边更快）
.venv\Scripts\python.exe -m pip install ultralytics `
    -i https://pypi.tuna.tsinghua.edu.cn/simple
```

装完自检：

```powershell
.venv\Scripts\python.exe scripts\train_yolo_fish.py --report
```

`--report` 只做环境与数据体检、**不训练**，会打印 torch / CUDA / GPU / 数据集体检结果。

### 2.1 踩过的坑（照抄命令前先看这里）

1. **wheel 文件名必须完整**。用浏览器下载时文件常被存成 `torch`、
   `torch (1).whl` 这类残缺名，`pip install torch.whl` 会直接报
   `ERROR: Invalid wheel filename (wrong number of parts): 'torch'`。
   改成规范名再装：
   `torch-2.8.0+cu128-cp313-cp313-win_amd64.whl`、
   `torchvision-0.23.0+cu128-cp313-cp313-win_amd64.whl`。
2. **GitHub 直连会 RST**。预训练权重 `yolov8n-cls.pt` 从 GitHub Releases 拉，
   直连报 `WinError 10054`。脚本内置了镜像前缀：
   `https://ghproxy.net/<原始 url>`、`https://gh-proxy.com/<原始 url>`，
   依次回退到直连（见 `scripts/train_yolo_fish.py` 的 `MIRRORS`）。
3. **ultralytics 会读你机器上别人的配置**。本机 `SETTINGS` 原先指向一个
   完全无关的 stable-diffusion 第三方整合包目录，
   导致自动下载的 `Arial.ttf`、`yolo26n.pt` 全落到那边去。
   已把三个全局目录改到本工程内：

   | 键 | 现值 |
   |---|---|
   | `weights_dir` | `<工程>\models\pretrained` |
   | `runs_dir` | `<工程>\data\derived\runs` |
   | `datasets_dir` | `<工程>\data\datasets` |

   注意 `ultralytics.utils.SETTINGS` **没有 `.save()` 方法**，
   要用 `SETTINGS.update({...})`，它会自行落盘（本机已实测新进程读得到）。
4. **`import ultralytics` 会偷偷把 `sys.stdout` 的编码改成 UTF-8**。
   在中文 Windows 的默认 GBK 控制台下，后果是脚本前半段按 GBK 写、加载模型
   之后按 UTF-8 写——**同一个输出流里混着两种编码**，终端上后半段整段变乱码，
   而**退出码是 0**，不报任何错。逐库实测只有它动编码：

   ```text
   import numpy:        'gbk' -> 'gbk'
   import cv2:          'gbk' -> 'gbk'
   import torch:        'gbk' -> 'gbk'
   import ultralytics:  'gbk' -> 'utf-8'   <== 只有它动了
   ```

   所以：**每个 `import ultralytics` 之后都要再调一次
   `fisheries.console.install()`**。`install()` 会锁住初次见到的编码并把它
   扳回来（它只放宽 `errors`，不改 `encoding`）。`fish_disease.py` 与
   `train_yolo_fish.py` 的每一处 ultralytics 导入后都已调用；搬代码时别漏。
   复验脚本：`scripts\probes\_verify_gbk_console.py`（7 个脚本零混编码）。

## 3. 数据：从哪来、怎么变成四分类

### 3.1 上游

用 `scripts\fetch_datasets.py` 统一管理（工程**不带**数据集，见
[`数据集说明.md`](数据集说明.md)）：

```powershell
.venv\Scripts\python.exe scripts\fetch_datasets.py --status
.venv\Scripts\python.exe scripts\fetch_datasets.py --fetch sb_fish_disease
```

三个图像源：

| 注册表键 | 内容 | 说明 |
|---|---|---|
| `fish_disease` | Train 1750 / Valid 350 / Test 350 / Train_Augmented 21358 | 主干数据集，7 类 |
| `freshwater_fish_disease_asia` | Train + Test 共 2450 文件，7 类 | 与上面高度重叠（去重后另增很少） |
| `sb_fish_disease` | 460 文件 / 7 类 | 上游 `SsekittoIsaac/SB-FishDisease`，**无任何标注框** |

### 3.2 去重：为什么最终只有 931 张

三份数据集**不是三份数据**。按文件内容 md5 比对：
`sb_fish_disease` 的 457 个唯一 md5 里 **456 个（99.8%）**已经出现在
`fish_disease` 的 23108 个唯一 md5 中；`freshwater_fish_disease_asia`
的 1747 个唯一 md5 同样有 456 个重复。

同一张图还常以 `.jpg` / `.jpeg` / `.png` 三种扩展名并存。因此构建脚本定义的
**图像身份 = (类别, 文件名主干)**，同主干多份文件时按扩展名优先级
（`.jpg > .jpeg > .png > .webp > .bmp`）再比文件大小取一份。

**结果：931 张真正不同的照片。**

### 3.3 四分类口径

用户只要求 健康鱼 / 烂鳃 / 细菌性出血 / 水霉 四类，
所以从上游 7 类里取 4 类、**明确舍弃 3 类**（理由写进报告，免得以后有人问"怎么少了三类"）：

| 上游类别 | 处置 |
|---|---|
| Healthy Fish | → `healthy` 健康鱼 |
| Bacterial gill disease | → `gill_rot` 烂鳃 |
| Bacterial diseases - Aeromoniasis | → `bacterial_hemorrhage` 细菌性出血 |
| Fungal diseases Saprolegniasis | → `saprolegniasis` 水霉 |
| Bacterial Red disease | ✗ 舍弃：红体病，不在指定的 4 类里 |
| Parasitic diseases | ✗ 舍弃：寄生虫病，属虫害而非细菌/真菌病害 |
| Viral diseases White tail disease | ✗ 舍弃：白尾病，病毒性且样本最少 |

### 3.4 构建命令

```powershell
# 自建 60/20/20 分层切分（种子固定，可复现）
.venv\Scripts\python.exe scripts\build_yolo_dataset.py

# 只看统计、不写任何文件
.venv\Scripts\python.exe scripts\build_yolo_dataset.py --report
```

产出 `data\derived\fish_disease_4cls\`：
**train 559 / val 186 / test 186**（合计 931），按类别分目录，即 YOLO 分类布局。

> ⚠ 切分是脚本**重新分层**做的，不沿用上游的 Train/Valid/Test 目录。
> 上游切分只用来记录"这张图原本属于哪个集合"。原因是三份来源的切分口径不一致，
> 混用会让同一张图（或其同主干的副本）同时出现在训练集和测试集里，指标虚高。

## 4. 训练

```powershell
.venv\Scripts\python.exe scripts\train_yolo_fish.py --epochs 60
```

脚本会自动：装/找预训练 `yolov8n-cls.pt` → 体检数据 → 训练 → 评估测试集 →
把指标写进 `data\derived\metrics.json` → 把 `best.pt` 复制成 `models\yolov8-fish.pt`。

常用参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--epochs` | 60 | 训练轮数 |
| `--imgsz` | 224 | 输入尺寸 |
| `--batch` | 32 | 批大小 |
| `--device` | 自动 | 如 `0` 指定第一块 GPU |
| `--workers` | 4 | DataLoader 进程数 |
| `--patience` | 20 | 早停耐心 |
| `--seed` | 0 | 随机种子 |
| `--report` | — | 只体检，不训练 |
| `--skip-build` | — | 不自动重建数据集 |

本机实测：`yolov8n-cls` 1,443,412 参数 / 3.4 GFLOPs，60 epoch
**0.018 小时**（约 65 秒，RTX 5070）。

## 5. 测试集结果（186 张）

| 指标 | 值 |
|---|---|
| Top-1 准确率 | **0.9301** |
| macro F1 | **0.9302** |
| mAP@0.5（弱口径，见 §5.2） | **0.9288** |

各类别：

| 类别 | support | precision | recall | F1 |
|---|---:|---:|---:|---:|
| healthy 健康鱼 | 45 | 0.8627 | 0.9778 | 0.9167 |
| gill_rot 烂鳃 | 46 | 0.9167 | 0.9565 | 0.9362 |
| bacterial_hemorrhage 细菌性出血 | 48 | 0.9773 | 0.8958 | 0.9348 |
| saprolegniasis 水霉 | 47 | 0.9767 | 0.8936 | 0.9333 |

共 13 张分错。混淆矩阵与全部错分样本（含预测置信度）见
`data\derived\metrics.json` 的 `confusion` / `misclassified_samples` 字段。

### 5.1 值得注意的错法

主要错法是**病害被判成健康**：`bacterial_hemorrhage` 有 4 张、`saprolegniasis`
有 2 张、`gill_rot` 有 1 张落进 `healthy`——一共 7 张。
这是远场/早期病害的典型漏检方向，比反过来（健康被判成病害）更危险，
因为漏检会让预警偏乐观。

对照组：`healthy` 只被判错 1 张（→ `gill_rot`，置信度 0.963，
从 `misclassified_samples` 看是一张视觉上确实可疑的图）。

### 5.2 ⚠ mAP@0.5 是"弱口径"，不能当检测指标用

**本数据集没有任何检测框标注。** 上游 SB-FishDisease 的 zip 里只有一个
`SB-Fish-Disease.csv`（列头 `Folder Name, Image Filename, Image Path`），
是纯图像分类口径；`fish_disease` 的三个来源目录同样零 `.txt`/`.xml`/`.json` 标注。

所以 `mAP50_weak_fullframe = 0.9288` 的算法是：
把每张图的真值"框"和预测"框"都当作**整图**，类别正确即 IoU = 1.0 ≥ 0.5，
于是它退化成"按置信度排序的分类 AP 均值"。

**它衡量分类排序质量，完全不衡量病灶定位能力。** 报告与
`metrics.json` 的 `mAP50_caveat` 字段都写明了这一点。
要算真正的定位 mAP，得先有框标注（`--det` 会用整图框训一个弱监督检测器，
那只是把同一件事换个口径算，仍然不是真定位指标）。

## 6. 权重怎么接进产品代码

`src/fisheries/tools/fish_disease.py`：

```python
_WEIGHTS_CANDIDATES = ("yolov8-fish.pt", "fish_disease_cls.pt")
DEFAULT_WEIGHTS_PATH = os.path.join(_MODELS_DIR, *_WEIGHTS_CANDIDATES[:1])

def resolve_weights(weights_path=None) -> str | None: ...   # 公开查询口
def _resolve_backend(weights_path) -> tuple[str, str | None]: ...
```

行为契约：

- 权重候选**按顺序找第一个存在的文件**；一个都没有 → 落 mock 后端，
  **不抛异常**，响应带 `degraded_mode=true` 和"这是演示结果"的提示语。
- 权重存在但 `ultralytics` 没装 → 同样落 mock。
- 调用方可以显式传 `weights_path` 或 `force_mock=True` 覆盖。
- 四分类训练输出的原始类名（`healthy` / `gill_rot` /
  `bacterial_hemorrhage` / `saprolegniasis`）**必须登记在
  `RAW_CLASS_TO_LABEL` 里**，否则真实推理会直接抛
  `模型输出的类别 xxx 未在 RAW_CLASS_TO_LABEL 中登记`。
  这条由 `tests/unit/test_tools.py::TestTrainingInferenceClassContract` 守着。

`/api/v1/health` 的申报（`src/fisheries/api/deps.py::describe_tools`）
**同时检查"权重文件存在"与"ultralytics 可导入"两个条件**。
曾经只查后者，于是"装了依赖但没训练权重"会谎报 `yolov8-cls`，
运维会误以为图像模态已上线——这个 bug 现在有专门的回归测试。

### 6.1 训好的权重放哪：外托管 + md5 校验

权重**不进版本库**（`models/*` 被 `.gitignore` 挡住，只放行 `models/checksums.md5`），
但要让评委和同事拿得到，所以采用「外部托管 + 仓库内钉校验值」：

```powershell
# 放在哪、多大、md5 是多少：README §3.6 的申报表；这里只记操作
.venv\Scripts\python.exe scripts\fetch_datasets.py --fetch-weights all     # 下载 + 自动校验
.venv\Scripts\python.exe scripts\fetch_datasets.py --weights --verify      # 只复核
.venv\Scripts\python.exe scripts\fetch_datasets.py --write-checksums       # 重训后刷新校验文件
```

- 校验分三级：先比 `models/checksums.md5` 的 md5，再比注册表（`src/fisheries/weights.py`
  的 `WEIGHTS`）里的 sha256 与字节数；对不上就删掉重下一次，两次都不对才报错。
- 镜像地址 `FISHERIES_WEIGHTS_MIRROR`（未配则回退 `FISHERIES_DATASET_MIRROR` 的 `weights/`
  子目录）；自建镜像 `python scripts/pack_dataset_mirror.py --weights --skip-datasets --out D:\share`。
- **重训后必须刷新校验**：先改 `src/fisheries/weights.py` 里 `WEIGHTS["fish_disease"]`（或
  `fish_lesion`）的 `md5` / `sha256` / `size`，再跑 `--write-checksums` 重写
  `models/checksums.md5`——两者由 `test_render_matches_the_committed_file` 逐字节钉住，
  只改一处不改另一处会红。忘了改也不要紧：`--write-checksums` 会先核本地文件，
  不一致时**拒绝写盘**并打印「应更新为 md5=… sha256=… size=…」，照着抄即可。
- **缺权重是显式的**：日志打 `权重缺失，将启用 mock 模拟模式：病害识别权重（models/yolov8-fish.pt）`，
  同一条只打一次；工具响应仍标 `degraded_mode=true`，不会静默给出假结论。

## 9. 病灶定位模型（YOLOv8n-seg，两类）

上文的 `models/yolov8-fish.pt` 只回答「是哪一类病」，**不告诉你病灶在哪、有多大**。
2026-10 补进来一批带真实多边形标注的鱼病图（203 张，去重后 201 张），于是多了
第二个权重 `models/yolov8-fish-lesion-seg.pt`：两类实例分割，`0: fish` / `1: lesion`。

### 9.1 数据长什么样、怎么清洗

源目录里图片和标签一一对应，但**标签是两种格式混装**的，这是第一个坑：

| 行数 | 格式 | 判据 |
|---:|---|---|
| 404 | 实例多边形 `class x1 y1 x2 y2 … xn yn` | 字段数 ≥ 6 且为偶数 |
| 30 | 轴对齐框 `class cx cy w h` | 字段数 = 5 |

把 5 字段的框当成「两点连线」会得到负宽度的荒谬框；反过来把多边形当成
`cx cy w h` 会读成四个坐标，全都错。`scripts/build_lesion_dataset.py` 的
`parse_line()` 先数字段数再决定解析方式，框统一展开成 4 个角点。

清洗做的事（全部记在 `data/derived/fish_lesion_seg/info.json`）：

1. **格式归一**：框 → 多边形；坐标夹到 `[0,1]`，面积小于 `1e-5` 的退化多边形丢弃；
2. **精确去重**：sha256 相同即同一张图（本次扔掉 2 张：`776` 与 `763`、`946` 与 `941`）；
3. **近似去重**：8×8 dHash，汉明距离 ≤ 4 视为同源，并查集合并成一个簇；
4. **按簇划分**：同一个簇整体进 train 或 val，避免同源图跨集造成泄漏；
5. **分层**：按「该图有没有病灶」分层，保证 val 里有足够阳性样本；
6. **重叠检查**：与 `data/datasets/` 现有数据比 sha256，防跨数据集泄漏。

本次结果：保留 201 张，训练 163 / 留出 38；实例 `fish 206 / lesion 228`。

> ⚠ **这份数据最大的缺口：201 张全是鱼，没有任何非鱼负样本。** 因此检测器学不到
> 「背景长什么样」，非鱼类图片（例如一张设计海报）照样会得到 0.83 的鱼框。要让它
> 真正拒绝非鱼类图片，往源目录里补几百张非鱼图片即可（`labels/` 放**空文件**，
> YOLO 里空标签就是「背景图」），然后重跑下面两条命令。

### 9.2 训练与指标

```powershell
.venv\Scripts\python.exe scripts\build_lesion_dataset.py --force
.venv\Scripts\python.exe scripts\train_lesion_seg.py --epochs 80 --imgsz 640 --batch 16
```

单卡 RTX 5070 Laptop 约 21 秒/轮，80 轮 ≈ 25 分钟，显存 3.4 GB。留出集 38 张 / 82 实例：

| | box | mask |
|---|---:|---:|
| mAP@0.5 | 0.969 | 0.969 |
| mAP@0.5:0.95 | 0.789 | 0.778 |

按类：`fish` P 0.967 / R 0.974 / AP50 0.990；`lesion` P 0.864 / R 0.907 / AP50 0.948 /
AP50-95 0.667。指标同时写进 `data/derived/lesion_metrics.json`。

### 9.3 权重怎么接进产品代码

`fish_disease_detect()` 会自动找 `models/yolov8-fish-lesion-seg.pt`（`_resolve_lesion_weights()`），
找到就跑一次检测，把 `lesion_count` / `lesion_area_ratio` / `lesions` 附在返回体里；
找不到就跳过，行为与之前完全一致。两个模型都参与时
`model_version = "yolov8-fish.pt+yolov8-fish-lesion-seg.pt"`，便于追溯。

**「是不是鱼」的门控默认是关的**（`enable_gate=False`）。原因是上面那个数据缺口：
实测那张设计海报得到 conf=0.830 的鱼框，而留出集里真实鱼最低也有 0.815，阈值分不开。
打开它（`enable_gate=True`）会走「没检测到鱼框 → `is_fish=False` → 四个结论字段全空」，
但只有补了负样本重训之后，这个开关才名副其实。

### 9.4 权重同样外托管、同样自动校验

`models/yolov8-fish-lesion-seg.pt` 与分类权重走同一套机制（见 §6.1）：
`python scripts/fetch_datasets.py --fetch-weights fish_lesion` 下载并核 md5
`93ce235e828481c003e1f577ab0f7149`（sha256 与字节数在 `src/fisheries/weights.py` 的
`WEIGHTS["fish_lesion"]` 里）。缺它时**不是假称有病灶**，而是打一条日志说明
「病害类型仍由分类模型给出，但没有病灶位置与面积」——分类结论不受影响。

## 10. 鱼种分类模型（YOLOv8n-cls，三个档位）

### 10.1 为什么只分三档

品种决定水质阈值的档位，而阈值表只有三套档案（鲤科 / 罗非鱼 / 虾蟹），
所以模型只需要回答「属于哪一档」，不需要认到种——认到种是另一个任务，需要分种标注，
而现有数据集的分种标签既不全也对不上本工程的品种命名。

### 10.2 数据从哪来

用 `fish_species_freshwater`（Kaggle `theshahidul/bangladeshi-freshwater-fish-image-dataset-bff-15`，
5,577 张、15 个孟加拉当地鱼种），按别名归到三档：

| 档位 | 来源类（数据集里的拼写） | 张数 |
|---|---|---|
| 鲤科 | `RUI`、`KATLA`、`MRIGAL`、`SILVER CARP`、`MIRROR CARP`、`PUTI`、`GRASS CARP`、`PUNTIUS`…（8 个类） | 2,569 |
| 罗非鱼 | `TELAPIA`（数据集把 Tilapia 拼成这个） | 383 |
| 虾蟹 | 虾数据集 `lokotwist/shrimp-disease-image-bd` 的 `ShrimpImages/ShrimpImages/Healthy` | 403 |

别名表在 `src/fisheries/tools/fish_species.py` 的 `RAW_SPECIES_ALIASES` 里；认不出的类
（`TENGRA` / `PANGAS` / `KOI` / `PABDA` / `SHOL` / `MAGUR` / `ILISH`，共 2,615 张）用
`--drop-unmapped` 丢掉，脚本会把丢掉的类与张数打印出来。**`KOI` 故意不映射**：孟加拉语里
KOI 通常指攀鲈（Anabas），不是锦鲤，硬映射会把攀鲈判成鲤科。

另外 500 张增强虾图（`Augmented_shrimp/Healthy`）只拼进**训练集**（`--extra-root 虾蟹=<目录>`），
不进验证集——增强副本与原图同源，跨集会让验证数字虚高。

### 10.3 构建与训练

```bash
# ① 把各来源目录挂成一个扁平根目录（junction / 软链都行，不复制文件）
python scripts/train_yolo_species.py --check --data-root data/derived/species_raw
# ② 训练（输出 runs/species，best 自动拷到 models/yolov8-species.pt）
python scripts/train_yolo_species.py --data-root data/derived/species_raw \
    --extra-root "虾蟹=C:\...\shrimp-disease-image-bd\versions\2\Augmented_shrimp\Healthy" \
    --drop-unmapped --epochs 60 --imgsz 224 --batch 32 --device 0
```

`--check` 会把每个档位的张数与丢弃的类打印出来；训练按 8:2 分层划分，落到
`data/derived/species_cls/{train,val}/<档位>`，清单写在 `data/derived/species_dataset_manifest.json`。

### 10.4 实际结果（2026-10-17，RTX 5070 Laptop）

| 项 | 值 |
|---|---|
| 训练 / 验证 | 3,186 / 669 张 |
| 轮数 | 上限 60，早停于第 39 轮（best 在第 19 轮） |
| 验证集 Top-1 | **100%**（top5 同为 100%） |
| 权重 | `models/yolov8-species.pt`，2,976,829 B，md5 `f8578ae043c7feb0fd5c637e704972db` |
| 耗时 | 约 8 分钟（0.128 小时） |

**这个 100% 要带着上下文看**：三档之间差异极大（鲤科 / 罗非鱼 / 虾，颜色与形状都不同），
而且训练图与验证图同源，同一条鱼的不同增强可能两边都有。它只用于选阈值档位，
不用于对外宣称「识别准确率 100%」。真正难的是同档位内认到种，那需要分种标注。

### 10.5 缺权重时会怎样

没有 `models/yolov8-species.pt` 时，`availability()` 返回 `available=False`，
接口 `GET /api/v1/species` 如实上报，前端把鱼种模块整块隐藏（不猜品种，也不 mock），
水质评估按默认品种（鲤科）走，下拉框仍可手动选。补权重：

```bash
python scripts/fetch_datasets.py --fetch-weights fish_species   # 外部托管（md5 自动校验）
python scripts/train_yolo_species.py ...                        # 或者自己重训
```
