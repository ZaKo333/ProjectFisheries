     这样 Agent 循环不会因为一次脏输入断链。

场景六  契约护栏（这些才是把 demo 变成系统的东西）
==============================================================================

[字段拼错] dissolved_oxygen 写成 dissolved_oxyen
  HTTP 422 → Extra inputs are not permitted
  → 契约是 extra="forbid"：拼错**报错**，而不是静默当成
     「没传溶氧」再算出一个没有溶氧的风险分。

[读数太少] 只传 2 条
  HTTP 422 → List should have at least 3 items after validation, not 2
  → 少于 3 条直接拒绝：否则工具会在样本不足时降级，
     调用方看到的是一个基于空水质的「正常」——假结论比报错更危险。

[未知 upload_id]
  HTTP 404 → 未知的 upload_id='deadbeef'；请先 POST /api/v1/ingest/image

[两模态都没给]
  HTTP 422 → 水质时序数据与鱼体图片至少要提供一项（readings / image_path / upload_id）

==============================================================================
  结论：接口层不重新实现业务逻辑——它只做四件事：
        校验入参、调用已实现的工具/Agent、把结果转成稳定契约、
        把异常转成明确的 HTTP 状态码。
